# 分块误报、旧修订写回与整页预览修复

## 原因与调整

- 全文口径原先依赖单个段落锚点；没有可靠位置时默认送到第一块。现在术语口径按正文实际出现位置分配到各相关批次，并传递全文首次出现位置。没有相关术语不是人工修改事项，不再把“本块没有”直接转成批注。无法解析的全篇要求交给所有分块，不局限于开头；不能仅因目标英文写法缺失就丢弃可能存在中文别名的要求。
- 原稿已有插入修订时，一个词可能横跨普通文字和旧插入节点。现在只将改动范围内的旧插入文字作为本次替换基线，保留未涉及的旧修订片段。真正跨超链接/容器的改动仍保守拒绝，并在最终预览前识别。一个run中有多个文本节点的边界也按独立编辑范围拆开。
- 原稿预览按原始页尺寸的80% 为上限，同时适配容器宽高。进入审阅时自动对齐到单屏工作区；右侧完整一页且没有滚动条，左侧清单独立滚动，点击修改只切换原稿页和高亮。人工事项仍在工作区下方。

## 验证与生效范围

- 离线重放用户已确认快照：9条修改全部写入、0条失败，结果全文与确认清单逐字一致；没有调用模型。验证脚本：`python -m scripts.verify_writeback_snapshot <隔离副本目录>`，不修改原任务或原稿。
- 回归覆盖：已有修订内及跨修订边界的替换、多文本节点保留周边文字、无关分块不报人工任务、真正需要人工处理的术语保留依据、各屏幕整页显示、长清单滚动不移动原稿。
- 验证结果：最终全量后端测试407 passed、1 skipped、23 subtests passed；随后补充别名保护用例，分块专项6 passed。浏览器端8项通过。已构建并更新本地应用容器，健康检查正常；更新前后任务均为16个已完成、1个等待用户、5个已取消。
- 新执行阶段使用修复后的逻辑；已有完成任务的结果文件和持久化确认清单不会被后台自动改写。重新导出历史任务需要明确选择其已确认方案，不能自动重新调用模型或覆盖用户选择。

这些测试验证执行逻辑与文档写回，不代表模型对论文事实的判断永远正确。
