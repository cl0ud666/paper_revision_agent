# 网页最终分页确认（2026-10-15）

## 产品流程

新建网页任务最多暂停两次：需要时集中选择一次术语/事实口径，然后最终分页审阅一次。不存在歧义时跳过第一次，不为凑次数打扰用户。后续发现的新歧义保留原文、转为建议。Web不再开启每轮patch_review；CLI / Streamlit保持原协议兼容。

最终审阅使用原始规范化DOCX经LibreOffice转成PDF，再渲染真实分页图像。左侧每项有编号、原文、修改后文字和原因；右侧原文红框与当前卡片通过箭头关联。支持双向定位、翻页、缩放、全选/全不选。勾选表示采用，取消表示保留原文。建议不出现在修改卡片中，只在最终Word中以“修改建议：”开头留批注。

结果页单独显示“未完成的修改及原因”框，仅列出最终确认清单中的用户取消、写回失败和有明确问题ID关联的复核未解决项。审查候选、未生成补丁、预览前定位失败、未展示的建议都不进入该框。预算和审查限制仍保留在处理记录及报告中。相同的清单范围校验也用于可下载报告。

## 一致性与恢复

- `prepare_report`节点冻结原稿→最终文字的独立修改清单和分页信息，先提交Checkpoint，再进入`final_confirm`中断。确认恢复后没有任何模型调用。
- 多轮改同一处合并成一项；按字符来源合并依赖，不使用模糊文本diff猜锚点。独立修改可分别取消；退回原文的无效修改消失。
- 原文、PDF字符流必须存在唯一的精确上下文匹配，且通过Word XML结构预检。无法定位的修改不允许写入，保留诊断记录并在可定位时转为建议；未展示的候选不列作已确认修改的失败。
- 实际Word正文再次对比已成功写入的选中清单，不一致则禁止交付。导出失败不伪装成功。
- 预览PNG在发布闸门前存入对象存储；另一个Worker恢复不要求本地PNG缓存存在。页面接口检查登录、论文所有权、冻结fingerprint和合法页码。
- 用户原件不覆盖。全不选且没有建议时返回规范化原稿；有建议时只有批注，不改变正文。

## 限制

预览接近Word原版式，不承诺与桌面Word像素一致。LibreOffice、字体替代、公式和浮动对象可能影响分页；DOC / WPS / RTF / ODT以转换后的规范DOCX为审阅基线，原上传件另行保留。

默认上限：150页、150M总像素、80MB PDF、160MB页面图像、100万渲染字符，转换120秒。超限或转换失败会保留原文并解释原因，不降级成伪造分页。需要进一步生产隔离时，应把文档转换器放入独立的无网络受限服务。

升级前已经创建的任务保持旧Checkpoint / 确认协议，不自动改写用户已有决定。体验新分页流程请重新上传新建任务。已下载的旧文件不会自动更新。

Word/WPS原生删除与插入仍是两条修订；删除批注不等于撤销正文。整项取消在网页最终确认中完成。本次不宣称修复桌面编辑器点击单个 × 的行为。
